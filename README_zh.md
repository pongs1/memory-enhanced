# 🧠 memory-enhanced — 基于证据的认知层 (V8)

[**English**](./README.md) | [**中文简体**](./README_zh.md)

> **“为什么你的 AI 总是记不住你昨天刚交代的代码风格？为什么解决过的 Bug 三周后又重演？为什么你的 Agent 在调用十几次工具后就迷失了方向？”**

`memory-enhanced` 插件将 OpenClaw 从一个“只有鱼的记忆”的对话框，进化为一个受**证据驱动** (Evidence-backed) 记忆架构与仿生联想唤醒控制的**长效智能体**。

---

## 🏗️ 架构概览：V8 的分层设计

V8 彻底抛弃了旧版的以事件为中心 (event-centric) 的 RAG 模型，转而确保所有记忆都能精确追溯到原始的会话证据 (Clean-Slate 默认模式)。整个处理流水线划分如下：

| 记忆层 | 职责 | 存储位置 / 产物 |
|---|---|---|
| **L0：控制层** | 当前活跃任务、优先级及焦点栈 (Focus Stack) | `.memory/active/focus_stack.json` |
| **L1：原始存储** | 不可变、仅追加的原始会话日志与运行时工具观察记录 | OpenClaw 会话与观察记录 |
| **L2-L5：流水线** | 归一化提取、分块化单元 (`micro/meso/macro`)、证据片段提取与边界内 IR 生成 | `.memory/graph/units.jsonl`, `evidence_spans.jsonl` 等 |
| **L6：记忆图谱与打包** | 3 层提取图谱 (`micro`, `meso`, `macro`)，以及记忆摘要包和状态包 | `.memory/graph/graph_nodes.jsonl`, `summary_packs.jsonl` |
| **L7：上下文组装** | 将激活的图谱 Bundle、状态和证据动态注入到大模型运行上下文中 | *运行时内存* |

*(完整的架构细节、Schema 定义与迁移计划，请参阅 [V8_ARCHITECTURE.md](./V8_ARCHITECTURE.md) 与 [V8_SCHEMA_AND_PIPELINE.md](./V8_SCHEMA_AND_PIPELINE.md))*

## 🧬 V8 核心黑科技：机器的灵魂

我们不再要求 AI 在数千个文件里“搜索”。取而代之的是，V8 依赖**在线点火 (Online Ignition)**与稀疏图谱传播机制。

### 1. 仿生扩散激活 (Biomimetic Spreading Activation)
系统扫描实时文本流与控制锚点，触发相关图谱节点的“点火”。能量会在稀疏网络中传播：
*   **前向与反向传播**：能量向前传递以模拟可能的后续发展，向后传递用于因果溯源。
*   **枢纽惩罚 (Hub Penalization)**：自动抑制高度连接的通用节点（如“API”），防止产生记忆噪音风暴。
*   **片段局部性 (Episodic Locality)**：利用日期和情景窗口来限制偶发记忆的激活，防止历史噪音淹没当前上下文。

### 2. 三层图谱拓扑
不同于扁平的知识图谱，V8 按照三种截然不同的语义环境组织记忆：
*   **Micro (微观)**：实体对象、事实及精确的证据锚点。
*   **Meso (中观)**：场景块、局部策略及工作流步骤。
*   **Macro (宏观)**：长期的阶段段落、全局状态及结构性转折点。

### 3. 即时修正循环 (热更新 Hot-Patching)
如果用户提出坚决的修正（“不对，请立刻改用 MySQL 而不是 Redis”），系统不会干等缓慢的离线图谱重建。它会立刻注入一个**影子节点** (`BeliefState: Revised`)，并对过时的旧事实施加巨大的负面惩罚权重，从而在在线上下文装配中瞬间完成热更新。

### 4. 程序记忆缓存 (Procedural Memory Caching)
为了避免大模型对已经盖棺定论的历史不断地重复推理消耗算力，V8 会主动限制这种冗余生成。高频触发且稳定的记忆簇（Activated Bundles）的输出会被缓存为 `记忆摘要包` 或 `结构化状态包`。这就像人类的“程序记忆”一样，将昂贵的陈述性推理转化为快速的结构性捷径。

## ⚡ 为什么避免使用旧版 Instruction Scripts (SKILL.md)？

1.  **证据优于脚本**：V8 将 `knowledge` 和 `skill` 视为事后归纳的产物 (packs)，而非原始证据来源。如果它们偏离了底层证据，就会开始衰减。
2.  **告别指令失明**：大模型经常无视长篇的指令脚本。但插件采用**原生代码执行**，无论大模型是否听话都能强制生效。
3.  **实时唤醒**：通过 ONNX 触发词典与高效索引器实现毫秒级响应。AI 再也不会因为“想不起来”而卡顿。

## 🚦 快速开始

1.  **拉取仓库**：将本项目克隆到 OpenClaw 的扩展目录。
2.  **安装环境**：执行 `pnpm install`。
3.  **配置**：修改 `openclaw.json` 开启插件模式与“强制注入”路径。
4.  **初始化**：在工作区创建 `memory/` 目录结构。

## 📜 任务管理哲学 (ADaPT)

本项目严格遵循 **ADaPT (Action Development and Project Tracking)** 框架：
1.  **被动式账本**：工作记忆 (L0 控制层) 永远以一个小型的任务账本形式被注入 (`目标 / 当前执行 / 下一步 / 延后 / 最近完成`)。模型无需主动“记着去查账本”。
2.  **用户请求至上**：最新的用户请求优先级永远高于系统存留的账本任务。账本空闲时，最新请求才会自动升级为 `Active`。
3.  **重排顺位而非思维漂移**：利用 `memory_working reprioritize`、`complete` 和 `defer` 指令推动长线项目的前进，拒绝让过时的陈旧任务劫持新的对话回合。
